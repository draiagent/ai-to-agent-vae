# 每週營運報告實作

本案例使用虛構數字。目標是驗收是否採用指定定稿，以及讀者能否追溯差異。

## 輸入與分工

營運負責人指定週次、定稿清單、差異門檻及完成時限。各部門確認定稿。Agent 彙整資料並產出草稿。主管核對並決定發布。

| 資料 | 前週 | 本週 |
|---|---:|---:|
| 營運部定稿／訂單數 | 100 | 115 |
| 客服部定稿／工單數 | 50 | 48 |
| 行銷部定稿／名單數 | 30 | 缺件 |

## VAC 任務指令

> 只使用清單中的定稿，將各項指標的前週、本週及差異百分比寫成週報草稿。絕對變動達 10% 就列為需確認，附上來源與欄位。缺件標記後交回原部門。遇版本衝突交由來源負責人確認。只交付草稿與來源對照表，發布交主管決定。

## 預期結果與驗收

- 訂單增加 **15%**，列入需確認並附營運部定稿的訂單欄位。
- 工單減少 **4%**，有來源且未達門檻。
- 行銷名單標為「缺件」，交行銷部補件。
- 確認兩項交付物齊全且週次正確。由人工記錄交代、製作、核對、補件及修改所花的總時間，供下次試跑比較。

## Capstone 八步驟

組隊分工 → 定義問題 → 臨時處置 → 找出原因 → 永久對策 → 同意操作 → 預防再發 → 核對資料。若用到舊稿，先請負責人指定本次版本，再檢查定稿管理，經同意後試跑新流程並逐筆核對。
